# Basic 1.0.0 delivery

Basic finds MCP servers for a task and presents their setup requirements with dated catalog evidence. The source application uses PostgreSQL and serves a browser interface plus three read-only Streamable HTTP tools: `search_servers`, `get_server`, and `get_setup_instructions`.

## Download and install

Download `basic_1.0.0_source.zip` and its `.sha256` file from the GitHub release. The ZIP contains the committed source, MIT license, dependency lockfile, 30 curated profiles, migrations and operator documentation. It does not include a database, dependencies or a built application.

Verify the downloaded checksum before extraction. On Linux:

```sh
sha256sum -c basic_1.0.0_source.zip.sha256
unzip basic_1.0.0_source.zip
cd basic-1.0.0
```

On macOS, use `shasum -a 256 -c basic_1.0.0_source.zip.sha256` for checksum verification.

On PowerShell, compare `(Get-FileHash basic_1.0.0_source.zip -Algorithm SHA256).Hash` with the checksum file, then use `Expand-Archive basic_1.0.0_source.zip`.

Install Node.js 24.x, pnpm 11.19.0, Git and Docker Compose. From the extracted directory, follow [local setup](SETUP.md):

```sh
pnpm install --frozen-lockfile
docker compose up -d --wait db
pnpm db:migrate
pnpm catalog:curate
pnpm build
pnpm start
```

Use a fresh database for this first installation. The default app address is `http://localhost:3400`; `/ready` reports readiness and 30 profiles after curation. If those ports are occupied, follow the setup guide to change PostgreSQL's published port and `DATABASE_URL`, and set `PORT` and `APP_ORIGIN` to the same application origin. Preserve existing databases and private environment files.

## Try the supported journey

1. Search for **I need a tool to search GitHub issues** and open the GitHub profile.
2. Inspect publisher sources, their dates, deployment requirements and verification history. Fresh curation starts with **Not tested** evidence; archived reports are not imported as new observations.
3. Try the documentation preset, open Microsoft Learn and expand a setup template. Configuration copying and JSON syntax do not prove installation in a third-party client.
4. Connect an SDK client to `http://localhost:3400/mcp`, or run `pnpm test:mcp` against your own running instance. The command lists and calls all three catalog tools and compares search results with the web API. It does not execute a publisher's tools.

Filters preserve explicit unknowns. A query such as **I need a tool for quantum gardening** returns no suitable matches. Missing profiles and malformed requests return bounded errors. Catalog evidence describes the recorded source or protocol observation; it does not certify third-party safety or guarantee task completion.

## Refresh and recover

Edit source-dated profiles and run `pnpm catalog:curate` for an offline catalog update. `catalog:sync` and `catalog:check` are explicit live operator actions with different scopes; read [OPERATIONS.md](../OPERATIONS.md) before running them. Adding a profile does not approve its endpoint for checking.

Run `pnpm backup:test` for a disposable local PostgreSQL dump/restore check. Set `BASIC_DB_CONTAINER` when using a named Compose project. The check compares table counts and verifies full-text search after restoration, then removes its temporary database. Preserve and test an independent backup before upgrading a database you need to retain.

The [Linux deployment guide](../DEPLOYMENT.md) covers containers, HTTPS, a scheduled worker and backups. Those instructions require validation on the chosen host. A source release does not establish public HTTPS, firewall rules, an off-host backup, production rollback or production capacity. The separate [hosted Sites edition](https://basic-agent-tools.alx21.chatgpt.site) uses its own reviewed snapshot and deployment process.

## Release automation

The October 6, 2026 local candidate check used Windows, Node 24.19.0, pnpm 11.19.0 and PostgreSQL 17.6 in a disposable Docker project. Frozen installation, dependency audit, 52 tests, typecheck and the production build passed. Eight desktop/mobile browser journeys passed, followed by real HTTP SDK calls to all three catalog tools, 35 search acceptance cases and all 30 profile routes. A fresh GitHub search/profile journey displayed the original September 9 source date and **Not tested** evidence. The local dump/restore preserved 30 profiles, 30 registry records and 122 claims and returned full-text search results.

These observations cover the local source application. They do not establish an installed Basic plugin connection in the current chat, a production Linux deployment, or remote release completion. The GitHub workflow must pass on the exact commit before publication.

Pull requests and manual workflow runs validate without publishing. A main push can publish `v1.0.0` after application validation (audit, tests, browser, SDK, acceptance, recovery and containers) and source packaging pass. The publisher uses only artifacts from that run, checks SHA256, rejects a tag or draft belonging to another commit, verifies uploaded assets, and leaves an existing published release unchanged. It also verifies that main still points to the validated commit before creating or updating a draft, creating a tag, and publishing.

After changing source for a future release, update the stable package version and changelog together. Commit a clean tree before running `pnpm package:release`; Git's archive includes committed files only. Private environment files, dependencies, build output and local backups are excluded from the source package.
